## 3. Code changes (this commit)

### LinkedIn leads, paced like a person (`naukri_bot/main.py`, `naukri_bot/portals/linkedin_posts.py`)

Before this change, one `leads` run did about 5 searches in a single browser session. More than that triggered
LinkedIn's 48-hour pause. Now:

```bash
.venv/bin/python -m naukri_bot leads --sessions 4 --break-minutes 4-9
```

- `--sessions N` splits the searches into N batches. Each batch opens LinkedIn, runs its searches, then closes
  the browser, and the run takes a random 4–9 minute break before the next batch.
- With `--sessions` above 1 and no `--queries`, it uses `wide_queries()`: 12 roles (AI / GenAI / LLM / ML engineer,
  data scientist, Python / backend / full stack / software engineer, AI-ML developer, Node.js, MLOps) times
  5 phrasings ("share resume", "send cv", "email resume", "immediate joiner", "hiring"). That's 60 searches,
  shuffled so no two runs search in the same order.
- Inside a session, scrolling is uneven: random scroll depth and count, and occasional 4–10 s pauses. There are
  25–60 s between searches.
- It stops early if LinkedIn pauses the account, or if 3 searches in a row return nothing.
- A 4-session run takes about 75 minutes. On 5 Nov one run found 256 new hiring posts, 203 with an email address.

Output: new posts go to `output/leads/linkedin_posts.csv`. The run also writes
`output/leads/outreach_<timestamp>.md` with raw drafts.

**The auto drafts are not good enough to send as they are.** Titles come out as hashtag strings, greetings
use the wrong name, and fresher, US-only and relocation posts slip in. The flow that worked:

1. Load the new rows from `linkedin_posts.csv`. Drop addresses already in `state/outreach_sent.json` and
   repeats within the batch.
2. Read each post. Skip:
   - US-only, Europe or abroad relocation, fresher and internship posts
   - non-tech jobs, vendor or partner calls, and job seekers' own posts
   - very low stipends
   - roles asking for 6+ years in a stack he doesn't lead with
   - companies already emailed that day

   Otherwise send, even when the years are a bit short (see the rules above).
3. For each send, choose a clean role title, a greeting (the poster's first name, or "Hello" for company pages),
   and a location. Choose one fit paragraph by role type: AI/LLM, full stack, Python backend, Java backend or
   data science.
4. Tailor a resume per post. `tailored_pdf(post_text, title, company, url="mailto:...", compact=True)` from
   `naukri_bot.tailor_rules` returns `(pdf_path, report)`, with `report["ats"]`.
5. Send with `tools/applemail_send.applescript` (below), 45–90 s apart, and append each address to
   `state/outreach_sent.json` (`{"at": ..., "source": "linkedin post (Apple Mail)", "title": ...}`).

Email shape (no links in the body; contact line only in the signature):

```
Hi {name},

I saw your post about the {title} role{ at company, city} and would like to apply. I have about two years of
experience {fit paragraph with 1-2 concrete numbers from the resume}.

I'm an immediate joiner (my last day at my previous job was 20 Oct). My resume is attached, and I'd be glad to talk.

Thanks,
{name}
{phone} | {email}
```

Subject: `Application for {title} - {name} (immediate joiner)`.

The bot's own `outreach` command still skips leads whose posts ask for many more years
(`experience_too_far_for_email`) and has a daily cap (`OUTREACH_DAILY_CAP`, default 15). Leads it skips can
be sent by hand with the flow above.

### Apple Mail sender (`tools/applemail_send.applescript`, new)

```bash
osascript tools/applemail_send.applescript "to@x.com" "Subject" body.txt resume.pdf "Name <sender@gmail.com>"
```

It prints `true` when Mail accepts the message. Check Mail's Sent mailbox (`[Gmail]/Sent Mail`) for the first
send of a batch. On 5 Nov a missing script made a whole batch fail silently, so check the first one before
queueing the rest.

### Security-code dialog (`naukri_bot/ats/generic_form.py`)

When an employer form emails a verification code (Greenhouse and others), the bot brings Apple Mail forward and
shows a macOS dialog where the candidate types the code. The bot never reads the code from the mailbox: the code
proves a person is applying.

### Screening answers (`naukri_bot/rules.py`, tests in `tests/test_rules.py`)

From forms on 2 Nov (Canonical, YipitData, Volga Partners, Lingaro, Supabase):

- Essay prompts ("Describe your experience with Kubernetes") get the profile's written answers, not "3 years".
  "How many years of X" still answers 3.
- A form with a single acknowledgement option ("I acknowledge this.", "I have submitted a PDF version of my
  resume.") gets ticked, except for criminal, disability, veteran and sponsorship questions.
- Time zone questions pick IST / India / UTC+5:30 / Asia Pacific.

All 214 tests pass.
