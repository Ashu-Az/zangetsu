## 1. Daily protocol now

1. **Naukri chain:** `refresh` → `tools/neo_apply.py` → `nvites` → `early-access` → `run --only naukri` (search is capped
   by `PRIORITY_RESERVE`; Neo gets the rest) → `outreach`.
2. **Other portals in parallel:** `portal wellfound`, `portal indeed`, `portal hirist`, `workday-run --submit`, then the
   Greenhouse/Lever/Ashby top-boards survey and `company-apply`.
3. **LinkedIn leads: once a day only.** A second `leads --sessions 4` run on the same day got search paused for 48 h
   (12 Nov). Run it in the morning; in the afternoon work the morning's unsent leads instead.
4. **Recruiter emails ("mail protocol"):** sources, in order:
   - LinkedIn hiring posts (`output/leads/linkedin_posts.csv`), screened by hand (see the 5 Nov handoff).
   - **Naukri job descriptions that contain a recruiter email** (`naukri_bot.outreach.naukri_leads()`, read from
     `state/survey.json`). On 13 Nov this gave 210 leads; drop anyone already in `state/outreach_sent.json`, broken
     scraped addresses (`and@switch.ensure`, `or@cognizant.company`), roles paying far below the current CTC, and
     senior / Java / .NET / non-tech titles. Send each with a resume tailored to its JD via
     `tools/applemail_send.applescript`, 45–90 s apart.
   - The bot's own `outreach` drafts still need the manual review: they repeat already-rejected posts.
5. **Instahyre** (new, see section 3) and the freelance platforms (section 4).

## 2. Bot changes in this commit

### Neo (`tools/neo_apply.py`)
Neo's question step changed on 12 Nov: it now offers *Fill answers with Neo / I'll answer myself / Skip this job*
instead of *Add missing details*. The bot clicks **I'll answer myself** so the questions are answered by the rules and
the candidate's own answers, never Neo's guesses.

### Questionnaire drawer (`naukri_bot/questionnaire.py`)
- **Quick-reply chips** (`.chatbot_Chips .chatbot_Chip`) are a new input kind (`chip`). Some recruiter questions only
  show chips (a single "Yes" for a privacy consent), and the drawer used to stall.
- A chip question whose only chip is **"Skip this question"** really wants the text box: the bot types its answer
  there instead of skipping (13 Nov: a last-working-day question was skipped and the candidate was rightly angry).
- Chatbot chatter ("No worries, you can change your input") is no longer treated as a question. A stale cached "2"
  was being sent as its answer.

### Rules (`naukri_bot/rules.py`)
- **Notice period counts the days left** to `last_working_day` while `serving_notice` is true (`_days_to_lwd`), so the
  answer shrinks every day; "soonest start" gives the day after the last working day.
- Last-working-day questions are **never skipped**: with only a Skip chip offered, the date is typed.
- `relieved: true` in the profile (left the last job, not yet joined) answers employment status "not currently
  employed" and "resigned: yes". Not used while serving notice.
- New answers: US export-control self-identification (Databricks), data-processing consent boxes (HighRadius, Okta),
  "current firm", pass-out year, expected CTC / stipend, counter offers / offers in hand (profile
  `has_current_offers`).
- Essay prompts that reached the model with mixed-up facts now come from `canned_answers` in the profile
  (SFT + RL projects, vector databases, achievements, a SQL story, payments data, visualisation tools).

### Resume tailoring (`naukri_bot/tailor_rules.py`)
The ATS top-up was pasting Naukri page text into the summary ("Skills highlighted with ‘…’ are preferred keyskills",
"Interview evaluation") and 50+ phrases at once. It now drops quoted/page-text phrases and anything longer than three
words, and adds at most 22 missing + 10 list-only skills. Scores after the fix: about 74–93 on real JDs, one page.

### Wellfound (`naukri_bot/portals/wellfound.py`)
Since 12 Nov Wellfound confirms with a toast ("Your application to X will be sent in a few minutes" + Undo) and an
"improve your odds" AI-interview modal. The bot now reads that toast sentence (not the sidebar's "Applied" link), so
real applications are no longer logged as failures.

Tests: 218 pass (`.venv/bin/python -m pytest -q tests`).

## 3. Instahyre

- The account existed but was set to *student or fresher*, 0 years, internships allowed, title "Fresher - interned
  at …". That is why its feed was all internships. Onboarding (`/candidate/onboard/`) was redone: working
  professional, full-time only, real title / company / previous companies, industry *Computer Software / IT /
  Internet*, 20 skills, current salary, notice, resume.
- Applying: *View job* → *Apply* → accept the "Apply to N similar jobs" popup. The confirmation text is not always
  visible to the script; trust the **Applied jobs** counter instead (53 on day one).
- **Recruiters reply within minutes with a questionnaire link** (`/questionnaire/<job>/<id>`) in the Instahyre inbox
  and by email. Check the inbox after every apply round and answer them (years per skill, notice / last working day in
  the format asked, CTC, 1–5 self-ratings).
- Sign-in is the candidate's own (Google). The bot never types passwords.

## 4. Freelance AI-training platforms

- **Micro1** (jobs.micro1.ai): applications for coding / RL-environment roles need a short AI interview by the
  candidate before any work is offered. Tool lists on some roles are scientific-simulation packages; pick "Other"
  and describe real tools rather than claiming ones the interview would expose.
- **Turing** (work.turing.com): drafts need a short interest form, then a 4–6 h take-home within 48 h. Submit only as
  many forms as the candidate can actually take tests for.
- **Take-home assessments are the candidate's own work.** Do not write them for him or disguise AI output as his:
  two Handshake AI projects were already closed for "assessment integrity" irregularities. Help by explaining,
  planning and reviewing instead.
